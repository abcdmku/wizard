# OpenTelemetry

`@openwizard/opentelemetry` turns a run's event stream into workflow, step-attempt, compensation, and nested run spans. You need it when an OpenTelemetry pipeline already exists and should show run timing and failures.

```sh
npm install @openwizard/opentelemetry @opentelemetry/api
```

```ts file="packages/docs/snippets/packages/opentelemetry.mts"
```

1. `instrumentRun(run)` subscribes to the run's events before `start()` so it sees the whole lifecycle.
2. The workflow span opens on start; step attempts and child runs become child spans.
3. Failures set the span status; successes leave it unset unless `successStatus` is on.
4. `telemetry.stop()` ends open spans and unsubscribes.
5. Dispose the run after stopping instrumentation.

## Options and handle

| Export | What it does |
|---|---|
| `instrumentRun(run, options?)` | Attaches spans and returns a `RunInstrumentation` |
| `tracer`, `parentContext` | Tracer to use; parent of the root workflow span |
| `resumeContext` | Context from an earlier process, added as a span link |
| `recordEvents` | `'none'`, `'lifecycle'` (default), or `'all'` |
| `children`, `instanceId`, `onError` | Trace child runs; instance id handling; adapter error hook |
| `span(path)`, `context(path)`, `inject()`, `extract()` | Read or propagate the current span context |
| `send(event, payload, options?)` | Link the incoming trace context and forward `eventId` and `correlationId` to the run |

Pass the delivery's stable id as `eventId` when the sender may retry. The run's persisted deduplication window handles repeats; instrumentation returns the same duplicate result as `run.send()`.

## Boundaries

Your application configures the SDK, tracer provider, and exporter; this package only calls the OpenTelemetry API. By default no context, input, output, event payload, idempotency key, or error message is copied into spans. Turn on extra attributes only after deciding what your tracing backend may store.
