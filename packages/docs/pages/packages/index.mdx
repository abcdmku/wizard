# Overview

Every application installs `@openwizard/core`; add another package only when a run crosses a boundary such as React, a database, several workers, tracing, or HTTP.

| Package | Adds | Install when |
|---|---|---|
| [`@openwizard/core`](/packages/core) | Wizard definitions, local runs, outcomes, snapshots, events, replay | Always |
| [`@openwizard/react`](/packages/react) | Typed hooks over a run or a browser mirror | React renders the run |
| [`@openwizard/devtools`](/packages/devtools) | Live graph, event log, timeline, step inspector | You need to see why a step is waiting |
| [`@openwizard/durable`](/packages/durable) | Leases, fencing, deduplication, timer claims | Several processes can touch one run |
| [`@openwizard/drizzle`](/packages/drizzle) | PostgreSQL and SQLite tables for durable records | Durable needs a real database |
| [`@openwizard/effect`](/packages/effect) | Effect 4 step adapters using the runtime in wizard deps | Your runnable work is an Effect program |
| [`@openwizard/opentelemetry`](/packages/opentelemetry) | Spans created from run events | An OpenTelemetry pipeline already exists |
| [`@openwizard/http`](/packages/http) | A run API, signed incoming events and outbound callbacks over HTTP | Browsers or external systems call the run |

## Typical stacks

A CLI or single Node.js server needs core only, plus a core `Store` when a run must outlive the process. A React app adds `react`, and `devtools` during development. A multi-worker service adds `durable` and `drizzle`. Add `opentelemetry` and `http` when tracing or external HTTP callers appear. Use `effect` when runnable work already uses Effect programs.
