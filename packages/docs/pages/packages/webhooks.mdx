# Webhooks and HTTP

`@openwizard/webhooks` connects HTTP requests to OpenWizard without choosing a web framework. It can verify incoming event webhooks, expose selected run operations, and sign outgoing callbacks.

```sh
npm install @openwizard/webhooks @openwizard/core
```

The request lifecycle is:

1. Your HTTP framework passes the standard `Request` object to `deliveredWebhook.handle(request)`.
2. The resource reads the signed body and verifies it with the configured secret.
3. `resolveRun` finds the run that should receive the event. A real application usually uses an id from the URL or verified payload.
4. The resource calls `run.send('delivered', payload)`.
5. The flow's event schema validates the payload before the active wait handler receives it.

A valid signature proves the request knows the secret. It does not decide which tenant or run the request may access. Make `resolveRun` enforce that authorization.

The literal secret is only for the snippet. Load production secrets from your platform's secret manager. If the sender retries deliveries, store its message id and return the earlier outcome instead of applying the same event twice.

The package also exports `defineRunAPI()` for selected state reads and commands. Your application supplies authentication, run lookup, and projections. `createWebhookSubscriptions()` stores outgoing subscribers and signs callbacks, but your application still chooses delivery storage and retry policy.

Read the exact contracts before exposing either resource on a public route. This package handles request parsing and signatures, not the rest of your application's authorization model.
