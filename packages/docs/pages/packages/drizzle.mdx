# Drizzle

`@openwizard/drizzle` implements the [Durable](/packages/durable) store contract on PostgreSQL and asynchronous SQLite through Drizzle ORM. You need it when workers coordinate through a shared database.

```sh
npm install @openwizard/drizzle @openwizard/durable drizzle-orm
```

```ts file="packages/docs/snippets/packages/drizzle.ts"
```

1. `defineSqliteDurableSchema()` returns Drizzle table definitions prefixed with `workflow_`.
2. Export those tables from your schema module so Drizzle Kit sees them.
3. Generate and run a migration with your normal Drizzle workflow.
4. Pass your database and the same tables to `createSqliteDrizzleDurableStore(db, tables)`.
5. Give that store to `createDurableHost(wizard, { store })`.

## Exports

Import from `@openwizard/drizzle/pg` or `@openwizard/drizzle/sqlite`.

| Export | What it does |
|---|---|
| `definePgDurableSchema(options?)` | PostgreSQL tables for snapshots, leases, dedupe, and timers |
| `createPgDrizzleDurableStore(db, schema, options?)` | Adapts a PostgreSQL Drizzle database to `DurableStore` |
| `defineSqliteDurableSchema(options?)` | The same tables for async SQLite drivers |
| `createSqliteDrizzleDurableStore(db, schema, options?)` | Adapts an async SQLite Drizzle database to `DurableStore` |
| `tablePrefix` (schema option) | Namespaces the table names |
| `leaseTtlMs`, `timerClaimTtlMs`, `retention` (store options) | Lease timing and record cleanup |

## Boundaries

The package returns table definitions; it does not open connections, generate migrations, or run them. Choose a `tablePrefix` that cannot collide with your other tables. Keep the generated tables in one migration so the durable contract updates as a unit. Store protocol types such as `DurableStore` and `Version` come from `@openwizard/durable/store`.
