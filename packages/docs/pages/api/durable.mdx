# Durable API

The generated [`@openwizard/durable` reference](/typedoc/modules/_openwizard_durable.html) covers durable hosts, leases, command deduplication, and timer claims.

Read the [Durable guide](/packages/durable) first.

| Export | Purpose |
|---|---|
| `createDurableHost(wizard, options)` | Host runs by key; owns leases, renewal, takeover, and disposal |
| `createDurableRun(wizard, options)` | Acquire a lease and create or resume one run |
| `resumeDurableRun(wizard, options)` | Acquire a lease and resume an existing record only |
| `createMemoryDurableStore(options?)` | In-memory `DurableStore` for tests |
| `createHostRegistry(open)` | Keyed host cache with invalidation |
| `DurableRunHost` | Run plus lease, commit, dedupe, and timer gates |
| `DurableRunOpenResult` | `ok` result or a failure code with `retryAt` |

`createDurableHost` returns `create(key, input)`, `open(key)`, `send(key, event, payload, { eventId, correlationId? })`, `dispatch(key, command, { commandId })`, and `dispose()`. Supplied wizard dependencies travel into these runs; an optional `deps(key)` supplies the remaining services.

## Command recovery

A repeated `commandId` with the same command replays its stored result and version. Reusing it for a different command returns `DEDUPLICATE_CONFLICT`. The host recovers completed command results from their atomic snapshot commit. A command applied before a crash that has no recoverable final result returns `COMMAND_INTERRUPTED`; read the run state before using a new id. Outside services still need the task's `idempotencyKey`, because a worker can stop after an external effect but before committing its result.

`DurableCommandOptions.expectedVersion` is `{ epoch, seq }`. Completed receipts replay first. A new claim at the wrong stored version returns `CAS_CONFLICT`; a change during asynchronous parsing produces a committed `STALE` result that later retries replay.

## Store adapter entries

Import `DurableStore`, `Version`, `CommitInput`, lease, timer, and dedupe types from `@openwizard/durable/store`. A store must apply `CommitInput.applyDedupe` atomically with its snapshot write. The resulting `applied` claim prevents another owner from applying that command again. Result completion must commit atomically with the corresponding state.

Run `durableStoreContract` from `@openwizard/durable/testing` against each adapter. See the [durability guide](/advanced/durability) for ownership and takeover rules.
