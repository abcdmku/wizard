# Save and resume

Store a run as JSON and continue it later, in another process.

```ts file="packages/docs/snippets/learn/save-resume.ts"
```

- A snapshot is plain JSON. It holds the context, drafts, step outputs, errors, deadlines and child runs. It does not hold `deps` or the wizard, so resume with the same wizard and pass `deps` again.
- With a `store`, every state change schedules a write. `await run.save()` when the next action depends on that write. `autoSave: 'off'` writes only on `save()`.
- Finished steps stay finished. A step that was running when the process stopped runs again if it declares `idempotencyKey`. Otherwise it fails as `interrupted` and the run halts, so you can check the service before `run.retry(step)`.
- Keep `Date`, `Map`, functions and class instances out of context and outputs. A value that is not JSON fails the write with `SNAPSHOT_NOT_SERIALIZABLE`.
- A store saves one snapshot per key through `get`, `set` and `delete`. `createMemoryStore()` is for tests.
- One process owns a run at a time. If two can reach the same run, read [Run on a server](/production/server).

## Resume a snapshot from older code

Give the wizard a `version`. When a stored snapshot has another version, `resume(snapshot, { migrate })` calls `migrate(snapshot, from)` and resumes what it returns. `renameSteps(snapshot, { oldId: 'newId' })` handles a renamed step.
