# How it works

A flow is typed data. A `FlowRun` interprets it. Optional packages connect the run to storage,
HTTP, React, telemetry, and deployment hosts.

<Diagram name="system" />

Every command follows the same loop:

```text
command -> decide -> run effects -> commit state and RunEvent values
```

The run commits a complete batch before subscribers see it. Snapshots, projections, traces,
devtools, and outgoing webhooks all read that committed state or event stream.

Schemas guard data entering the run. Dependencies are trusted services supplied by the host.
Core persistence assumes one owner for each run. The durability package adds leases and fenced
writes when another worker may take ownership.

The flow definition contains no database, web framework, or cloud code. Start the model with
[Defining flows](/concepts/defining-flows).
