# Steps and kinds

A flow is a map of six step kinds. With the default `autoRun: 'ready'`, a ready task, wait,
decision, child flow, or final step starts automatically. A ready view becomes the current view.

| Kind | Purpose | Advances when |
|---|---|---|
| `view` | collect or review input | `next()` accepts its parsed draft |
| `task` | call a service or compute | its `run` function succeeds |
| `wait` | pause for an input event | a handler completes it or its timeout fires |
| `decision` | choose the next target | its `next` function succeeds |
| `flow` | run a child flow | the child finishes successfully |
| `final` | finish the run | its output function succeeds |

The file imports `order` from the [Defining flows example](/concepts/defining-flows), saved as
`order-definition.ts`.

`next` activates another step. `dependsOn` delays an activated step until its prerequisites
finish. Hooks receive typed `context`, `deps`, `step`, `path`, `signal`, and `update` values. A
hook that handles an output or input event receives the matching type.

Views retain drafts. Tasks can add output validation, retries, timeouts, idempotency, and
compensation. Wait steps are covered with [event inputs](/concepts/external-events). Flow steps are
covered in [Nested flows](/concepts/nesting).

Commands report normal rejections as values. Read [Results as values](/concepts/results) before
adding failure policies.
