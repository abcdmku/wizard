# Policies

A flow's behavior is its step kinds plus a handful of policies, and the policies are plain data
rather than code paths. There is no `mode` option: a pure wizard is a flow with only views, a DAG
is tasks with `dependsOn`, and a saga is tasks with `compensate` plus `onFailure: 'compensate'`.

| Policy | Where | Values | What it does |
|---|---|---|---|
| `onFailure` | flow | `'halt'` (default) \| `'compensate'` | What happens when a task fails with no retries left. |
| `retry` | flow default, per task | `RetryPolicy` | Retries after the first failure, spaced by `backoff`. |
| `timeout` | per task | `Duration` | Aborts the run through `signal`, then fails with `kind: 'timeout'` once the retries are spent. |
| `autoRun` | flow | `'ready'` (default) \| `'manual'` | Ready non-view steps start on their own, or wait for `runReady()`. |
| `concurrency` | flow | `number` (default `Infinity`) | The most tasks that can run at once. |
| `unmatchedEvents` | flow | `{ buffer: boolean; ttl: Duration }` | Events with no active listener are buffered in arrival order, or dropped. Default: buffer for `'5m'`. |

## `onFailure: 'halt'`

The default leaves a failed flow recoverable: once the retries are exhausted you get
`step.failed { kind: 'run' }` then `flow.failed { code: 'STEP_FAILED' }`, and `next()` comes back
rejected with `FLOW_TERMINAL`. `retry(step)` re-runs the task with the attempt counter reset, and
the flow carries on from there.

## `onFailure: 'compensate'`

The flow unwinds instead: running tasks are aborted, attempts already in flight are allowed to
settle (a late success is pushed onto the stack so it gets undone too), and then every completed
step with a `compensate` hook is undone in reverse completion order, one at a time, best effort.

```ts
const s = defineFlow({ name: 'book-trip', context: Trip, deps, onFailure: 'compensate' })

export const bookTrip = s.steps({
  reserveHotel: s.task(({ context, deps }) => deps.hotels.reserve(context.tripId), {
    compensate: ({ output, deps }) => deps.hotels.cancel(output.booking), // output is this task's own
    next: 'charge',
  }),
  // no compensate here: a failed charge has nothing to undo, it just starts the unwind
  charge: s.task(({ context, deps }) => deps.payments.charge(context.tripId), { next: 'confirmed' }),
  confirmed: s.final(),
})
```

A failed undo lands in `saga.failures` instead of throwing (`step.compensationFailed`), and
`compensate({ from })` re-attempts that entry later. The flow ends
`flow.compensated { outcome, failures }` and is terminal, and `cancel(reason?)` starts the same
unwind ([example 03](/examples/03-non-recoverable-compensation)).

## `retry` and `timeout`

A `RetryPolicy` is plain data, so `inspect()` can show it.

| Field | Meaning |
|---|---|
| `attempts` | Retries after the first failure, so `attempts: 1` means two runs total. |
| `backoff` | A fixed number of milliseconds, or `'exponential'`. Absent means retry immediately. |
| `baseMs`, `factor`, `maxBackoffMs` | Exponential waits `min(baseMs * factor^(attempt-1), maxBackoffMs)`, defaulting to 200 ms, 2, and 30 s. |

Retries are timers: each is a `step.retryScheduled { dueAt, timerId }` event, `explain(step)`
reports `phase: 'retrying'` in the meantime, and the attempt counter and `retryAt` deadline
persist so resume re-arms them ([example 02](/examples/02-recoverable-failure) drives one with
the test scheduler).

## `autoRun` and `concurrency`

With `'ready'`, every ready `task`, `wait`, `decision` and `flow` step starts by itself, tasks
respecting the `concurrency` limit in activation order. With `'manual'` they start on
`runReady()`, or `run(task)` for a single one, and `explain(step)` says `concurrency-limit` or
`auto-run-manual` while one waits.

## `unmatchedEvents`

A webhook can arrive before the step that handles it exists. By default it is buffered
(`event.buffered { expiresAt }`, visible in `state.inbox`) and delivered the moment a step that
handles it enters, expiring after `ttl` (`event.expired`); `buffer: false` drops it instead
(`event.dropped { reason: 'no-listener' }`).
