# Failures and retries

A task failure is stored on the step and emitted as run events. The default
`onFailure: 'halt'` stops new work but leaves the run recoverable through `retry`, `invalidate`,
`cancel`, or `compensate`.

This is the `reserve` step from [Defining flows](/concepts/defining-flows) with its execution
policies filled in.

`attempts` counts retries after the initial call. Retry deadlines persist with the run. A timeout
aborts the task's `signal`. It cannot force an external service to stop.

Set `onFailure: 'compensate'` on the flow to undo completed tasks in reverse completion order.
Each task supplies its own `compensate` function. Failed compensation is recorded and can be
retried later.

External task calls run at least once. A process can stop after a provider accepts a request but
before the run saves the result. Pass the stable `idempotencyKey` to the provider and have the
provider deduplicate it.

`autoRun` controls whether ready non-view steps start automatically. `concurrency` limits running
tasks. Both become useful when the graph branches in [Parallel work and joins](/concepts/dag).
