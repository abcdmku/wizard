# Persistence and resume

Core can store one JSON-safe snapshot per key. It assumes that only one live run owns the key.

```ts file="packages/docs/snippets/concepts/persistence.ts"
```

With a store configured, the run saves after each committed change by default. Resume checks the
flow name, version, step set, state invariants, and stored boundary values before it creates a live
run. A version change needs a `migrate` function.

Snapshots reject values that a JSON round trip would change, including `Map`, `Set`, `bigint`,
functions, and non-finite numbers. A `Date` is safe only where a boundary restores it from its JSON
form. Keep secrets in dependencies.

A task that was running during a crash is interrupted. An idempotent task restarts automatically
with the same key. A non-idempotent task becomes a recoverable interrupted failure. Timers resume
from their stored absolute deadlines.

Use [Durability and retries](/guides/durability) when several workers may own the same key. It adds
leases, fenced writes, request deduplication, and timer claims. Next, choose what may cross a
client boundary in [Projections and the Mirror](/concepts/projections).
