# Parallel work and joins

An array of `next` targets starts several branches. `dependsOn` holds the join until its required
branches finish.

```ts file="packages/docs/snippets/concepts/dag.ts"
```

`next` activates a step. `dependsOn` only delays an activated step, so every joined branch must
point to the join. An array in `dependsOn` requires every listed step. `{ any: ['a', 'b'] }`
requires either one.

`when` skips a ready step when its predicate returns false. A skipped step satisfies dependencies.
`skip(step)` does the same by command. `invalidate(step)` returns finished work to idle. By
default, it also invalidates completed or active transitive dependents.

`run.explain('join')` reports missing dependencies, concurrency limits, and other readiness
reasons. A `final` step cancels the other active branches, so join any required work before it.

A whole workflow can also be one step. Continue with [Nested flows](/concepts/nesting).
