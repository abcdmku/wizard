# Event inputs

OpenWizard uses "event" for three different contracts:

| Meaning | Source | API |
|---|---|---|
| input event | another system sends data into a flow | `run.send()` |
| run event | the runtime records a committed change | [`run.observe()`](/concepts/observability) |
| outgoing webhook | the delivery worker sends selected run events to subscribers | [Outgoing webhooks](/integrations/outgoing-webhooks) |

An input event needs a schema because its payload comes from outside the run.


`send` parses the payload before a handler sees it. The result names the active steps that received
the event. It also reports buffering, rejection, or a correlation drop.
Unmatched events are buffered for five minutes by default. `unmatchedEvents` changes that policy.
A correlation mismatch is dropped and never buffered.

A wait handler completes the step when it returns nothing. It can instead keep waiting, choose a
different target, provide an output, or fail. OpenWizard stores each timeout as an absolute
deadline and restores the remaining wait on resume.
