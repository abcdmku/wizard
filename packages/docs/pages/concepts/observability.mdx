# Run events

Each commit contains one or more `RunEvent<F>` values. The flow determines their step ids, input
payloads, step outputs, context patches, and final output types.


`orderFlow` is the flow from [Event inputs](/concepts/external-events). Call `observeOrder(run)`
before starting the run, and call the returned function to unsubscribe.

`observe` receives every event after its whole batch has committed. `subscribe` receives one state
notification per batch. `log()` returns this run's bounded event history, which keeps 200 events
by default. Descendant events reach the parent's observer but remain in the descendant's own log.
Descendant types retain the exact path, step ids, event payloads, contexts, and outputs through
the eight-level nesting limit.

Do not maintain another event-name registry. `RunEventType` and `RUN_EVENT_TYPES` expose the
runtime's canonical names. The [outgoing webhook integration](/integrations/outgoing-webhooks)
delivers selected run events without repeating their schemas.

Two diagnostics use the same model:

- `inspect(flow)` returns the static nodes, edges, and graph warnings.
- `run.explain(step)` returns the current phase and stable reasons that block the step.

Use [OpenTelemetry](/integrations/opentelemetry) to turn this stream into spans. Read
[Failures and retries](/concepts/policies) for the events produced by failed tasks.
