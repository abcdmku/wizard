# Overview

These pages cover what happens when a run stops halfway, waits longer than one process lives, receives duplicate messages, splits into branches, or exposes progress over a network. Each page opens with the smallest example that shows one feature; the sections below it go deeper.

## Pick the page for your failure

| You hit | Read |
|---|---|
| A call failed, and a restart may repeat it | [Retries and idempotency](/advanced/recovery) |
| A later step failed after earlier side effects | [Compensation](/advanced/compensation) |
| Branches must join typed results, or a collection needs bounded parallel work | [Graphs and parallel work](/advanced/graphs) |
| Saved state came from older code | [Snapshots and migrations](/advanced/persistence) |
| Two workers loaded the same run | [Multi-worker durability](/advanced/durability) |
| A webhook arrived early or for another run | [External event routing](/advanced/events) |
| A stage deserves its own run and snapshot | [Nested flows](/advanced/nested) |
| A browser needs a safe subset of state | [Projections and mirrors](/advanced/projections) |
| An operator asks why a step is stuck | [Explain, observe, replay](/advanced/operations) |

## What core does not do

- It cannot make a remote call exactly once. Pass the task's `idempotencyKey` to a service that enforces it.
- Compensation is a new side effect, not a rollback. It can fail, and the failure is recorded.
- There is no HTTP server, auth, or database driver in core. Your host owns those and feeds the run typed commands.
