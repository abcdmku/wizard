# Run on a server

Serve runs from several processes without two of them working on the same run at once.

```ts file="packages/docs/snippets/advanced/server.ts"
```

- A durable host gives one process at a time a lease on a run, and the store refuses writes from a process that lost it. Use a host as soon as two processes can reach the same run. Without one, both can resume the same snapshot and both call your services.
- `host.create(key, input)` creates the run at `key`, or opens the one stored there. `host.open(key)` opens only a run that exists.
- Send commands and events through the host, with `host.dispatch` and `host.send`. They check the ids and reopen the run when its lease was released or lost. Use `opened.host.run` to read state.
- Pass the caller's request id as `commandId` and the sender's delivery id as `eventId`. A repeat replays the stored result and changes nothing.
- When the wizard needs services, add `deps: (key) => ({ ... })` to the host options.
- Call `host.dispose()` on shutdown. It waits for commands in flight and releases every lease.

## Handle a refusal

Every call returns a value. Check `ok`, then `code`.

| Code | Meaning | Do |
|---|---|---|
| `LEASE_BUSY` | Another process holds the run | Try again at `retryAt` |
| `RUN_NOT_FOUND` | `open` found no run at the key | Create it |
| `LEASE_LOST` | Another process took the run during the call | Call the host again. It reopens the run |
| `DEDUPLICATE_CONFLICT` | The `commandId` belongs to a different command | Use one id per command |
| `CAS_CONFLICT` | `expectedVersion` is not the stored version | Read the run again |
| `COMMAND_INTERRUPTED` | The command was applied, and the process stopped before its result was stored | Read the run before you send a new id |

## Store runs in a database

```ts file="packages/docs/snippets/advanced/drizzle.ts"
```

`createMemoryDurableStore()` coordinates hosts inside one process. Processes on different machines need a shared database. [`@openwizard/drizzle`](/packages/drizzle) has stores for PostgreSQL and SQLite.

## Plan for a crash

- A lease lasts 30 seconds and the host renews it. When a process dies, another process takes the lease after it expires and resumes the run.
- The step that was running runs again there if it declares `idempotencyKey`. The host saves state before each step starts. It cannot save your service call, so [pass the key to the service](/learn/failures#retry-a-step).
- On a runtime that lives for one request, set `renew: 'manual'` and dispose the host before the request ends.
