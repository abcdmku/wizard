# Projections and mirrors

A projection chooses which run data a client receives. A mirror keeps a versioned copy of that view in sync over a transport. Use them when the server owns the run and the browser should see only selected fields.

This projection sends base run and step facts, the `payment` validation issues, `context.total`, and the final output. It omits `cartId` and the payment draft, which holds the token. Base facts include run id, epoch, sequence, status, current view, and each step's id, kind, status, phase, and attempt.

`input: true` exposes the whole selected draft, including any token fields. Use `select` to return only `last4` when the UI needs that field without the token.

## `expose` or `select`

`expose` picks from standard workflow state. `select` maps typed state into a custom client shape:

```ts
const summary = defineProjection(wizard, {
  select: (state) => ({ status: state.status, step: state.current }),
})
```

Pass the wizard itself. A projection works with that wizard and its `.provide()` variants. `run.project(projection)` checks the authored definition; a separate wizard with the same name is rejected.

## Progress stays private unless selected

`run.progress()` returns a step-count summary. With an `expose` projection, `expose.progress: true` sends that summary as state. Individual hook calls to `progress(value)` need a per-step flag. This example opts in for `work` and the nested child's `upload`:

```ts file="packages/docs/snippets/advanced/progress.ts"
```

A `select` projection opts in with a separate `progress` map beside its selector. The `expose` form puts each flag under the selected step and child spec. `expose.waitingFor: true` also sends the flat wait list.

These flags allow transient progress frames; they do not add progress fields to the selector's result. Omitting the flags sends no hook progress. A parent's flag does not expose a child's events automatically. Review progress payloads as carefully as state fields because they can contain private data too.

## Project mapped children

For a mapped child step, `child: true` exposes a readonly array of `ChildSummary | null` in input order. A nested child exposure spec produces a readonly array of projected `ClientState | null` instead. A `null` slot has no available child data; keep its position rather than filtering it out and shifting item indexes.

## Scoped selectors

A scoped projection requires an authenticated principal whenever it is projected:

```ts
const dispatchView = defineProjection(wizard, {
  scope: boundary.trusted<Viewer>(),
  select: ({ state, scope }) => ({
    allowedTenant: state.context.tenantId === scope.tenantId,
    current: state.current,
  }),
})
const state = run.project(dispatchView, viewer)
```

`ProjectionScope<typeof dispatchView>` recovers the principal type. Scope stays out of run context, commands, events, snapshots, frames, and acknowledgements. The wire parser rejects client-supplied scope. A selector can deliberately return principal fields, so test serialized output for every role.

## Mirrors

<Diagram name="projection" />

Import mirror and transport APIs from `@openwizard/core/mirror`:

```ts
import { createMirror, createMirrorSource } from '@openwizard/core/mirror'

const source = createMirrorSource(run, checkoutClient)
const mirror = createMirror<typeof checkoutClient>({ transport })
```

Frames carry `instanceId`, `epoch`, and `seq`; the mirror ignores older snapshot frames. Commands carry ids so acknowledgements match. Example 08 uses a local JSON transport. WebSocket or HTTP/SSE can carry the same protocol, including `httpTransport` from `@openwizard/http/client`.

`Frame` is a union of snapshot and progress frames. Check `frame.kind === 'snapshot'` before reading `frame.state`. `mirror.observe(listener)` receives allowed transient `step.progress` events; a disconnect can lose them. Snapshot subscriptions continue to carry committed projected state.

## Authorize at the source

```ts
const source = createMirrorSource(run, dispatchView, {
  scope: viewer,
  authorize: ({ state, command, scope }) =>
    state.context.tenantId === scope.tenantId &&
    scope.role === 'operator' &&
    (command.type === 'setInput' || command.type === 'next'),
})
```

Create one source per authenticated principal. It parses each command and checks its run instance before calling `authorize`, which may be async. A denial, throw, or rejection returns a generic `FORBIDDEN` acknowledgement without changing machine state. Look up the run within the tenant first; projection does not grant access to it.
