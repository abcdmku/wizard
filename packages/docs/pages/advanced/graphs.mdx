## Join typed outputs with `needs`


`needs` supplies both data and activation. Neither producer needs `next: 'average'`. Every hook on `average` receives the same typed `needs` object.

| Need | When the consumer can run | Value in its hooks | If a producer is skipped |
|---|---|---|---|
| `needs: { result: producer }` | Producer completes | Producer output | Consumer skips with `needs-skipped` |
| `needs: { result: { any: [a, b] } }` | First producer completes | Union of producer outputs | Consumer skips only if all producers skip |
| `needs: { result: { optional: producer } }` | Producer settles | Output or `undefined` | Consumer receives `undefined` |

A plain need requires a step object, not an id string. References in `next`, `targets`, `dependsOn`, and `fallback` accept either spelling. Optional needs change data availability; producer failures still follow their failure policy.

An event wait that times out is a skipped producer, with reason `timeout`. The table applies to it: a plain need skips the consumer, an `any` need waits for another producer, and an optional need supplies `undefined`.

## `dependsOn` gates activation

`dependsOn: [a, b]` waits until both are `done` or `skipped`. `{ any: [a, b] }` waits until one is. It supplies no hook data and does not start the consumer. Activate that consumer with `next` or include it in `start`.

A false `when` skips a branch. A control gate can still run; a consumer with a required `needs` value skips because there is no value to read. Choose the gate based on whether the consumer needs that result.

## Declare branch targets

```ts
choose: step({
  targets: ['fast', 'review'],
  next: ({ context }) => context.total < 100 ? 'fast' : 'review',
})
```

A function `next` requires `targets`. Its return type and its runtime result must stay within that list. An invalid or throwing selector fails the step under the wizard's failure policy.

The runtime skips unchosen targets with `not-taken`, then propagates that skip along static edges when every predecessor was skipped. Required needs propagate skips too. `inspect(wizard)` warns about an AND-join over exclusive targets. If a blocked dependency can no longer activate, the join fails with `DEPS_UNREACHABLE` instead of waiting forever.

## Map over a collection

```ts file="packages/docs/snippets/advanced/patterns.ts" lines="24-39"
```

`each` snapshots the items when the step starts and returns results in input order, even when calls finish out of order. `concurrency` bounds the number of item calls. A `key: (item, index) => string` can name items; keys must be unique.

Completed item results live in the snapshot. Resume keeps those results and recovers interrupted items according to `idempotencyKey`. Each item follows `retry`; if one exhausts its retries, the step fails while keeping completed results. `run.retry('fetch')` retries failed items. Every completed item emits transient `step.progress` with `{ done, total }`.

## Manual execution and invalidation

With `autoRun: 'manual'`, use `run.startReady()` to start ready work or `run.startStep('normalize')` for one runnable step. Views and event waits do not consume the run-function concurrency budget.

`await run.invalidate('normalize')` resets it and, by default, its transitive dependents. Running dependents are cancelled first. Old output moves to `previousOutput`; context changes never invalidate work automatically. Reactivate the step through a predecessor's edge before starting it again.

Parallel hooks read context as it was when each hook started. Use `update(current => ({ count: current.count + 1 }))` when a patch depends on the latest committed value. The updater applies atomically; a captured `context.count + 1` can lose a concurrent increment.
