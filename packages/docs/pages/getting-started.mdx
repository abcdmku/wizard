# Build a wizard

OpenWizard runs a typed graph of steps. A step can collect input, run work, wait for an event or a timer, choose a branch, or run a child wizard. A run keeps its context, outputs, drafts, and deadlines while execution pauses.

The [core API reference](/api/core) lists options. The [production guides](/advanced) explain persistence and hosting.

## Install

```sh
npm install @openwizard/core zod
```

Core runs in browsers and server JavaScript runtimes with timers, promises, and `AbortController`. Repository tooling requires Node.js 20 or newer. Zod is optional; any Standard Schema validator works.

## Define and execute

```ts file="packages/docs/snippets/learn/factory.ts"
```

`defineWizard(options, build)` calls the builder once. The callback creates steps, then returns `steps(map, { start? })` to check references against the assembled map. Schemas infer context and input; functions infer step outputs. The first step starts by default.

The returned Wizard is the definition itself. Pass it directly to `inspect(wizard)`, `defineProjection(wizard, ...)`, `createHTTP(wizard, ...)`, or a durable host. Every call to `wizard.create(input)` produces independent run state.

`runSync` returns a discriminated outcome and disposes its run. Check `status` before reading `output`. If a callback returns a promise or execution needs a timer, it throws `SYNC_VIOLATION` with the step name.

## Collect input

```ts file="packages/docs/snippets/learn/factory-form.ts"
```

`create(input)` validates starting context and returns an idle Run. `start()` enters `contact`. `setInput` merges a draft; `next()` validates it and follows the edge only after validation succeeds. Invalid input produces `ok: false` with issues.

The view's `exit` receives parsed `output`. Here, `output.email` is a string and `update` commits it to context. `go`, `setInput`, and `child` accept only appropriate step IDs.

Keep a live Run while a user edits input or a server waits for an event. Dispose it when its owner unmounts or shuts down. [React](/packages/react) supplies subscriptions without adding UI code to the definition.

## Run work and supply services

```ts file="packages/docs/snippets/learn/factory-services.ts"
```

`step({ run, ...options })` infers the awaited return value. It accepts retry, timeout, compensation, error mapping, and fallback. The wizard's `output: ({ context }) => ...` selector computes its final result after work and exit hooks finish. This selector is synchronous.

Put database clients and other services in `deps`. They never enter snapshots. `provide` returns a new Wizard and tracks the keys it supplies. Providing only `log` leaves `lookup` required. Providing both lets this example call `run` without a deps option.

`DepsOf<typeof wizard>` describes all services hooks receive. `RequiredDepsOf<typeof providedWizard>` describes the services still required at creation. Provided services also reach child wizards, HTTP run creators, and durable hosts. Per-run deps can override a provided key.

## Join typed outputs

```ts file="packages/docs/snippets/recipes/parallel.ts"
```

Create producers first, then refer to their step objects in `needs`. The join starts when both producers finish, even though neither declares a `next` edge to it. `needs.loadProfile` and `needs.loadOrders` have their producer's output types.

These options answer different questions:

| Option | Meaning |
|---|---|
| `next` | Activate the named step or steps after this step finishes |
| `dependsOn` | Gate a step that another edge already activated |
| `needs` | Wait for typed producer data and activate the consumer |

A plain need requires its producer's output. `{ any: [a, b] }` uses the first completed producer's output. `{ optional: a }` permits a skipped producer and supplies `undefined`. A skipped required need skips its consumer; an any need skips only if all alternatives skip. Read [graphs](/advanced/graphs) for branch joins and item maps.

## Compose wizards and step modules

```ts file="packages/docs/snippets/learn/factory-composition.ts"
```

A module is an ordinary function returning named steps. Spreading modules into the map checks references against the whole graph. Keep distinct keys; object spread overwrites duplicates.

Pass a child Wizard directly to `flow(child, { context })`. The child owns its context and output. The parent's `exit` receives the child output after the child finishes. Provided child services stay attached to the child. The parent must supply or map the child's remaining required services.

A dynamic `next` must declare `targets`. Unchosen targets become skipped, which lets joins distinguish an untaken branch from unfinished work. Use a separate `step({ waitFor })` before work that needs an event. A view or runnable step can use `on` for events delivered while it is active.

## Choose the execution boundary

| Method | Behavior |
|---|---|
| `wizard.create(input, options?)` | Validate synchronous creation boundaries and return a live Run |
| `wizard.createAsync(input, options?)` | Await creation boundary validation and return a live Run |
| `wizard.runSync(input, options?)` | Return a synchronous outcome and dispose the run |
| `wizard.run(input, options?)` | Return when terminal, halted, or parked on a view or external event, then dispose |
| `wizard.resume(snapshot, options?)` | Restore a live Run with synchronous boundary validation |
| `wizard.resumeAsync(snapshot, options?)` | Restore a live Run with asynchronous boundary validation |

Async work functions work with `create`. `createAsync` is needed when creation boundaries validate asynchronously.

Convenience execution returns `done`, `failed`, `cancelled`, `halted`, or `waiting`. Halted and waiting outcomes include a snapshot you can resume. Step failures are outcomes; invalid starting context and other API misuse can still throw.

For a live Run, `whenIdle()` waits for the current drain, `awaitOutcome()` waits for the next terminal or parked state, and `awaitResult()` waits only for a terminal result. `awaitOutcome` keeps the Run alive. Pure sleeps and retry backoff keep async convenience execution going.

`runSync` checks synchronous execution at runtime. TypeScript cannot prove that every nested callback or service is synchronous. It cannot undo an external side effect started before a callback returns a promise.

## Keep private data at the host

Import the same Wizard in browser tests, a UI, and a server. Inject platform-specific services at the host. Core opens no database connections.

A snapshot contains context, drafts, outputs, and errors. Use a [projection](/advanced/projections) for a server-owned run's client state. Hook progress is transient, but its payload can still contain private data. Forward it only through explicit per-step progress exposure.

The public constructors accept object configurations only. Assembly checks step references and needs cycles. Duplicate step objects and some identical-type reference mistakes still need runtime checks. Untrusted input still needs schemas even when TypeScript accepts a caller's type.
