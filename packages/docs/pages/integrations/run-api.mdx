The run API lets an authenticated client read selected state and dispatch allowed commands.

## Authenticate the caller

The application owns token verification. Pass that function into the auth factory. Save it as
`auth.ts`:

```ts file="packages/docs/snippets/http/auth.ts"
```

Resolve account membership while verifying the token. Scopes decide what the caller may do.
`tenantId` decides which run the data layer may return.

## Look up the live run

The data layer returns the one live run owned by this process. Save this in `runs.ts`:

```ts file="packages/docs/snippets/http/runs.ts"
```

`RunDataLayer` is a live-run lookup, not a persistence adapter. A Redis or PostgreSQL host stores
snapshots, leases, and request ids. It opens one run for the lease lifetime and returns that owner:

```ts file="packages/docs/snippets/http/leased-runs.ts"
```

For Redis, implement `DurableStore` with atomic lease and compare-and-set operations. For
PostgreSQL, use the [Drizzle durable store](/integrations/drizzle). Both hosts can use the adapter
above. Do not resume a new `FlowRun` for every HTTP request. The
[durability guide](/guides/durability) defines the ownership contract.

## Create the API

Save the registry factory as `http.ts`:

```ts file="packages/docs/snippets/http/http.ts"
```

For this flow, OpenWizard derives `/api/orders`, `orders:read`, and `orders:command`. Override the
path, id, or scopes only when those defaults do not fit.

| Route | Purpose |
|---|---|
| `GET /api/orders/{runId}` | read selected run data |
| `GET /api/orders/{runId}/steps/{step}` | read selected step data |
| `POST /api/orders/{runId}/commands` | dispatch an allowed command or input event |

## Document OAuth scopes

An OAuth provider can inherit the scopes generated by the registry:

```ts file="packages/docs/snippets/http/oauth.ts"
```

The same provider inherits `orders:webhooks:read` and `orders:webhooks:write` when the registry
also includes [outgoing subscriptions](/integrations/outgoing-webhooks).

Use [incoming webhooks](/integrations/incoming-webhooks) when the sender signs an input event
instead of authenticating as an API client.
