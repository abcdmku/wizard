# Views and input

A `view` pauses the run at a form. It stores a draft, validates it when your application moves on, and supplies the accepted value to `exit`. Copy the fields later steps need into context there, or pass the view's output to a consumer through `needs`.


1. `start()` enters `contact`. Status is `waiting` and `state.current` is `'contact'`.
2. `setInput('contact', patch)` shallow-merges the patch into the draft and clears issues for changed fields.
3. `next()` parses the whole draft with `input`. On success the parsed value becomes the step's output, `exit` runs, and the run follows `next`.
4. The final step reads the accepted data and completes.

`setInput()` stores the draft. `next()` attempts to leave the view.

## Invalid input

```ts
const moved = await run.next()

if (!moved.ok && moved.reason === 'validation') {
  console.log(moved.code) // 'INVALID_INPUT'
  console.log(moved.issues) // [{ message, path }]
}
```

The run stays on the view, `exit` does not run, and nothing reaches context. Render the issues and let the user edit the draft. `run.validate('contact')` checks without trying to move. `canEnter` and `canExit` can also refuse navigation.

## Draft and context are separate

The draft belongs to the view while it is edited. Context holds data shared with later steps. Copy accepted fields in `exit`:

```ts
exit: ({ output, update }) => update({ email: output.email }),
```

`back()` preserves the draft and does not run the view's `exit` hook. If a later step needs the view's accepted output directly, reference the view in `needs: { contact }`.

## Initial drafts

`initial` seeds the draft from a partial object or a function of `context` and `deps`:

```ts
profile: view({
  input: profileInput,
  initial: ({ context }) => ({ plan: context.selectedPlan }),
  next: 'done',
}),
```

OpenWizard stores the resolved draft, so back navigation and resume keep it. `resetInput('profile')` clears it and runs the initializer again. An initializer that throws fails the view.

A view can handle declared events through `on`. To require approval before entering the form, place a separate `step({ waitFor })` before it.

## Where data is checked

| Boundary | Checked by |
|---|---|
| Starting context | `wizard.create(input)` |
| View draft | `next()`, `go()`, `validate()` |
| Event payload | `send()` |
| Work output | The step's optional `output` schema |

`boundary.trusted<T>()` supplies a type without checking values at runtime. Use it for data your host already checks, such as service dependencies.
