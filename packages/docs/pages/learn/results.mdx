# Commands, state, and outcomes

An application needs the response to its command, the run's current state, and the outcome of its work. OpenWizard gives each a separate value.

```ts
const moved = await run.next() // response to this command
const state = run.getState() // current state
const outcome = await run.awaitOutcome() // terminal, halted, or waiting
```

## Command results

`start()`, `setInput()`, `next()`, `send()`, `retry()`, and other commands return results. Check `ok` before reading success fields:

```ts
const moved = await run.next()
if (!moved.ok) console.error(moved.code, moved.message)
```

`ok: true` means the command was applied. A successful `start()` can leave the run waiting at a form. Invalid input and commands refused in the current state return `{ ok: false, code, message }`; validation failures also carry `issues`.

Cancelling a run while navigation is pending aborts that navigation. Its result has `ok: false`, `reason: 'failed'`, and `code: 'CANCELLED'`.

Runnable work starts automatically by default. Set `autoRun: 'manual'` in the wizard options to control it yourself. `run.startStep('load')` starts one ready runnable step and `run.startReady()` starts the ready set. Their command responses describe whether the command succeeded, not whether the run finished.

## Commands based on a state version

Use `dispatch(command, { expectedVersion })` when a command depends on state your application read earlier. Capture `{ epoch: run.epoch, seq: run.getState().seq }` with that read and pass it as `expectedVersion` when dispatching.

OpenWizard checks both `epoch` and `seq` atomically when it processes the command, after queued work and any asynchronous payload check. A mismatch returns `STALE` without applying the requested action. Read the current state before deciding whether to issue another command. Including `epoch` also detects a resume since the version you read.

## State

```ts
const { status, current, active, context, steps } = run.getState()
```

| Field | Meaning |
|---|---|
| `status` | `idle`, `running`, `waiting`, `halted`, `done`, `failed`, `compensating`, or `cancelled` |
| `current` | The current view, or `null` |
| `active` | Active step ids, including the current view |
| `context` | The typed shared data |
| `steps` | Per-step `status`, `attempt`, `input`, `output`, and `error` |

`getState()` is synchronous. `subscribe(listener)` follows committed state changes. `observe(listener)` follows events, including transient progress. `run.waitingFor()` lists the current views, event waits, and sleep deadlines. Its flat entries include a `path`; `[]` identifies this run, `['address']` identifies an ordinary child, and `['batch', '0']` identifies the first mapped child under `batch`. Mapped path segments use the input index as a string.

## Outcomes when work pauses

`awaitOutcome()` resolves when a run ends, halts, or parks on input from a person or external system. It leaves the run alive so you can recover or send the missing input.

```ts
const outcome = await run.awaitOutcome()
if (outcome.status === 'halted') {
  console.error(outcome.failure)
} else if (outcome.status === 'waiting') {
  console.log(outcome.waitingFor)
}
```

Both `halted` and `waiting` outcomes carry a `snapshot`. Save it and resume later, or keep the live run and continue. Pure sleep timers and retry backoff keep `awaitOutcome()` waiting for work to proceed.

Use `wizard.run(input, options?)` when you want the outcome without owning a live run:

```ts
const outcome = await order.run({ orderId: 'o-42', total: 42 }, { deps: { payments } })
if (outcome.status === 'done') console.log(outcome.output)
```

The convenience method creates, starts, awaits the outcome, and disposes its run. To continue a waiting or halted outcome, call `order.resume(outcome.snapshot, options)`. `wizard.runSync()` returns the same outcome types synchronously and throws `SYNC_VIOLATION` when a hook returns a promise or a timer is needed.

## Terminal results

`awaitResult()` waits for `done`, `failed`, or `cancelled`. It stays pending through a recoverable halt or an external wait, so use it only when your application will continue driving the run.

```ts
const result = await run.awaitResult()
if (result.status === 'done') console.log(result.output)
```

| Result | Meaning |
|---|---|
| `done` | Carries the options-level `output` selector result, or the last completed sink's output |
| `failed` | Carries a terminal failure and any compensation summary |
| `cancelled` | Carries the cancellation reason and any compensation summary |

A run stopped for manual recovery has `status: 'halted'`, not `failed`. It can accept `retry`, `skip`, `compensate`, or `cancel`. `awaitResult()` rejects with `RunLifecycleError` if you reset or dispose before a terminal result. See [retries and failures](/learn/failures).

## What throws

Step failures are outcome values. Boundary rejection while creating a run, incompatible snapshots, and definitions with invalid references throw `WizardError`. A typed event name must belong to the wizard; untrusted event payloads are checked by `send()` and return rejection results. Commands issued after disposal return `DISPOSED`.
