# Overview

Start with [Build a wizard](/getting-started) for a complete definition and run. These pages explain the same API one behavior at a time.

| Page | You learn |
|---|---|
| [Wizards and runs](/learn/mental-model) | A wizard is a definition; a run records one execution |
| [Step kinds](/learn/steps) | Work, typed joins, event waits, timers, views, and children |
| [Views and input](/learn/input) | Drafts, validation, and moving accepted data into context |
| [Commands, state, results](/learn/results) | Command responses, live state, parked outcomes, and terminal results |
| [Retries and failures](/learn/failures) | Retry policies, fallback, halted runs, and manual recovery |
| [Events and waiting](/learn/events) | Declaring events and delivering them to a waiting step |
| [Save and resume](/learn/persistence) | Snapshots, stores, and continuing after a restart |
| [Testing](/learn/testing) | Driving a run in a test without a server or UI |

Read the first four pages for a local wizard that runs code and collects input. Continue when a run must survive a restart, wait on another system, or recover from failure.

The [Production](/advanced) section covers idempotency, compensation, graphs, migrations, worker ownership, projections, and replay.
