# Use a child flow

Use `flow(childWizard, config)` when one stage is a workflow of its own, such as an address wizard shared by checkout and account settings. Pass the child wizard itself.

## What happens

1. The parent reaches `address` and calls `context` to build the child's input.
2. OpenWizard checks that value against the child's context schema.
3. The child runs with its own state while the parent step stays active.
4. The child's completed output becomes the parent `address` step's output.
5. The parent follows its declared `next`, or completes when this was its final step.

## Separate runs, explicit data

Parent and child each own their context, drafts, and step records. The `context` mapper supplies child input, and the child returns its completed output. A later parent step can consume it with `needs: { address }`.

The child also needs its services. Dependencies bound with `childWizard.provide(deps)` travel with it. OpenWizard can use compatible parent dependencies for remaining services; when they do not satisfy the child's requirements, the `deps` mapper is required.

A child halt halts the parent for recovery. `fallback` on the parent flow step can route around a halted or failed child instead. A parent `awaitOutcome()` includes waits in its children, with paths that identify the flow step.

## Reach the live child

```ts
const child = run.child('address')
child.getState()
await child.next()
```

`child()` accepts ids of `flow` steps. An ordinary child takes only its step id. Parent snapshots contain child snapshots, so children resume with the parent. Dispose the parent when you no longer need either run.

## Run a child for each item

Add `each` when every item needs the same child workflow. The `context` and `deps` mappers receive `item` and `index`; `concurrency` bounds active item children. The parent step returns child outputs in input order and retains finished item results across resume.

A mapped child requires a selector. Use `run.child('batch', 0)` for the first input item, or `run.child('batch', 'order-42')` for its configured item key. The selected child must be live. Public event and wait paths use the input index, such as `['batch', '0']`, even when you selected by key.

Mirror commands use numeric indices, such as `mirror.child('batch', 0)`. React bindings also use `useChild('batch', 0)`. Ordinary children use `mirror.child('address')` or `useChild('address')` without a selector. See [React](/packages/react) for child bindings.

After an item fails, `run.retry('batch')` retries failed items and keeps completed child results. The mapped flow step is part of `RetryStepId<typeof wizard>`.
