# Branch on data

Use `step({ next, targets })` when current data picks one of several paths.


## What happens

1. The run enters `choose` and calls `next` with the current context.
2. The function returns the `express` or `standard` step.
3. OpenWizard activates the selected target and skips the other with reason `not-taken`.
4. The selected branch finishes. With no remaining work, the wizard completes with that sink's output.

## Declare dynamic targets

A function `next` must declare the full set of targets it can return:

```ts
const choose = step({
  targets: [express, standard],
  next: ({ context }) => context.speed === 'express' ? express : standard,
})
```

Targets can be literal ids or step objects. OpenWizard checks them against the assembled map and checks the callback's return against its targets. An invalid return or thrown error fails the step under the wizard's failure policy.

For a later data join over mutually exclusive targets, use `needs: { delivery: { any: [express, standard] } }`. A plain need for each branch would skip the join when the untaken branch skips. Use an optional need for a branch whose value may be absent.

## Skip an optional action

Use `when` when a step may be omitted while the sequence continues:

```ts
gift: step({
  run: wrapGift,
  when: ({ context }) => context.gift,
  next: 'done',
}),
```

If `when` returns false, the step skips and follows its ordinary `next`. A plain `needs` reference propagates the skip to its consumer. An optional need lets the consumer run and read `undefined`.

## Keep routing pure

Choose the path from data the run already has. Put database or HTTP calls in runnable steps so retries and errors belong to the operation that can fail.
